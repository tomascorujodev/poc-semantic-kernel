## 1. What is Semantic Kernel?

**Semantic Kernel (SK)** is Microsoft's open-source SDK for adding AI to normal applications. It is available for **C#/.NET**, **Python** and **Java**.

It sits between **your code** and an **LLM** (Large Language Model). It handles:
- sending prompts and receiving answers,
- letting the model call your own functions (**plugins**),
- connecting to your data (**RAG** with vector stores),
- building **agents** that can work in several steps and collaborate.

You write normal C#. SK handles the details of talking to the model.

> ℹ️ In late 2025 Microsoft announced the **Microsoft Agent Framework**, which combines Semantic Kernel and AutoGen. SK is still supported, and its concepts (kernel, plugins, function calling, agents) carry over to the new framework. This PoC uses Semantic Kernel.

## 2. Key concepts

### General AI concepts

| Concept | Meaning |
|---|---|
| **LLM** | A model that generates text from a prompt, such as GPT-4.1, Claude or Llama. |
| **Prompt** | The text or instructions you send to the model. |
| **Token** | The unit of text a model counts, roughly ¾ of a word. You pay per token. |
| **Context window** | The largest number of tokens the model can read in one request. |
| **Temperature** | How random the output is. 0 gives the most predictable answers; higher values give more creative ones. |
| **Embeddings** | Text converted into number vectors so you can search by meaning. *(Used in Step 3.)* |
| **RAG** | Retrieval-Augmented Generation: search your documents and add the results to the prompt. *(Step 3.)* |
| **Function calling** | The model asks your code to run a function and then uses the result. *(Step 2.)* |
| **Agent** | An LLM with instructions, tools and memory that can complete tasks in several steps. *(Step 4.)* |

### Semantic Kernel concepts used in this step

| Concept | What it is | Where it is in the code |
|---|---|---|
| **Kernel** | The central object. It holds AI services and plugins, and everything runs through it. | `KernelFactory.Create()` |
| **Kernel builder** | Configures the Kernel before it is created, using dependency injection. | `Kernel.CreateBuilder()` |
| **AI service / connector** | The adapter for a model provider (Azure OpenAI, OpenAI, Ollama…). | `AddAzureOpenAIChatCompletion(...)` |
| **Prompt template** | A prompt with variables, written as `{{$variable}}`. | `Program.cs` |
| **KernelArguments** | The values that fill the template variables. | `new KernelArguments { ["topic"] = ... }` |
| **InvokePromptAsync** | Renders a template, sends it to the model, and returns the result. | `Program.cs` |

## 5. Azure setup (Microsoft Foundry)

### 5.1 How Azure organizes Foundry

```
Subscription
└─ Resource group: PocSemanticKernel
   └─ Foundry resource: PocSemanticKernel     ← has the ENDPOINT and KEYS
      ├─ Project: poc-semantic-kernel          ← a workspace, NOT a model
      └─ Model deployments
         └─ gpt-4.1-mini                       ← the DEPLOYMENT NAME used in code
```

> ⚠️ **Resource, project and deployment are three different things.** The code connects to the **resource endpoint** and selects the model by **deployment name**.

### 5.2 Steps we followed
1. **Create the Foundry resource and project.** In the Azure portal, we created a Microsoft Foundry resource. The wizard created the resource `PocSemanticKernel` and the project `poc-semantic-kernel` in the resource group `PocSemanticKernel`.
2. **Deploy a model.** In the Foundry portal (https://ai.azure.com): open the project, go to **Models + endpoints**, then **+ Deploy model → Deploy base model**. Choose `gpt-4.1-mini` with deployment type **Global Standard**. The deployment name is `gpt-4.1-mini`.
3. **Get the endpoint and key.** In the Azure portal, open the resource `PocSemanticKernel`, then **Resource Management → Keys and Endpoint**.
   - Endpoint: `https://<resource-name>.openai.azure.com/`
   - Key: **KEY 1**

## 7. Configuration and secrets

### Why User Secrets?
API keys must **never** be written in code or committed to Git. **User Secrets** stores them in your Windows user profile, outside the project folder:

```
%APPDATA%\Microsoft\UserSecrets\<UserSecretsId>\secrets.json
```

### Settings

| Key | Example value | Notes |
|---|---|---|
| `AzureOpenAI:Endpoint` | `https://<resource-name>.openai.azure.com/` | The **resource** endpoint, not the project URL |
| `AzureOpenAI:ApiKey` | `********` | KEY 1 from "Keys and Endpoint" |
| `AzureOpenAI:ChatDeployment` | `gpt-4.1-mini` | The deployment **name**, without `< >` |

```powershell
cd src/PocSemanticKernel
dotnet user-secrets set "AzureOpenAI:Endpoint" "https://<resource-name>.openai.azure.com/"
dotnet user-secrets set "AzureOpenAI:ApiKey" "<KEY 1>"
dotnet user-secrets set "AzureOpenAI:ChatDeployment" "gpt-4.1-mini"
```

> In examples, `<...>` only marks where your value goes. **Don't type the brackets.**

### Environment variables (alternative)
On a server or in CI, use environment variables. In .NET, a double underscore `__` stands for `:`.
```powershell
$env:AzureOpenAI__Endpoint = "https://<resource-name>.openai.azure.com/"
$env:AzureOpenAI__ApiKey = "<KEY 1>"
$env:AzureOpenAI__ChatDeployment = "gpt-4.1-mini"
```

## 8. The code explained

### `KernelFactory.cs`

```csharp
public static IConfiguration LoadConfiguration() =>
    new ConfigurationBuilder()
        .AddUserSecrets<Program>()       // local dev
        .AddEnvironmentVariables()       // CI/servers (these override user secrets)
        .Build();
```
This loads the settings. Later sources override earlier ones, so environment variables win over User Secrets.

```csharp
public static Kernel Create(IConfiguration config, LogLevel logLevel = LogLevel.Warning)
{
    var endpoint = Required(config, "AzureOpenAI:Endpoint");
    var apiKey = Required(config, "AzureOpenAI:ApiKey");
    var chatDeployment = Required(config, "AzureOpenAI:ChatDeployment");

    var builder = Kernel.CreateBuilder();                                   // 1
    builder.AddAzureOpenAIChatCompletion(chatDeployment, endpoint, apiKey); // 2
    builder.Services.AddLogging(l => l.AddConsole().SetMinimumLevel(logLevel)); // 3
    return builder.Build();                                                 // 4
}
```
1. **Kernel builder**: a dependency-injection container for SK.
2. **AI service connector**: registers an `IChatCompletionService` that talks to your Azure OpenAI deployment.
3. **Logging**: SK writes its logs here. The default level is `Warning`; change it to `Information` or `Debug` to see more.
4. **Build**: creates the immutable `Kernel`.

`Required(...)` throws a clear error if a setting is missing, and the message includes the exact `dotnet user-secrets set` command to fix it.

### `Program.cs`

```csharp
var config = KernelFactory.LoadConfiguration();
var kernel = KernelFactory.Create(config);

var result = await kernel.InvokePromptAsync(
    "Explain {{$topic}} in two short sentences for a beginner developer.",
    new KernelArguments { ["topic"] = "Microsoft Semantic Kernel" });

Console.WriteLine(result);
```
- `{{$topic}}` is a **template variable**.
- `KernelArguments` supplies its value.
- `InvokePromptAsync` does three things: it **renders** the template, **sends** the prompt to the chat service, and **returns** a `FunctionResult`.
- Behind the scenes, SK turns this prompt into a temporary **KernelFunction**. That's why the error logs say `Function (null)-InvokePromptAsync_...`.

## 10. Troubleshooting: problems we hit and how we fixed them

| # | Error | Cause | Fix |
|---|---|---|---|
| 1 | `HTTP 400 (BadRequest) API version not supported` | The endpoint was the **project** URL: `https://<name>.services.ai.azure.com/api/projects/poc-semantic-kernel` | Use the **resource** endpoint: `https://<name>.openai.azure.com/` |
| 2 | `HTTP 404 (DeploymentNotFound)` | `ChatDeployment` was set to the **project name** (`poc-semantic-kernel`), and no model had been deployed | Deploy `gpt-4.1-mini` in Foundry and set `ChatDeployment` to `gpt-4.1-mini` |
| 3 | *(avoided)* Value saved as `<poc-semantic-kernel>` | The `< >` brackets from the documentation examples were typed | Type the value without brackets |

### Other common errors

| Error | Cause |
|---|---|
| `401 Unauthorized` | The key is wrong, or it belongs to a different resource |
| `429 Too Many Requests` | You exceeded your deployment's quota (tokens per minute). Wait and retry, or increase the quota in Foundry |
| `Missing setting 'AzureOpenAI:...'` | A secret isn't saved. Check with `dotnet user-secrets list`, but don't share that output, because it shows the key |

## 11. Lessons learned
- **Resource ≠ project ≠ deployment.** Connect to the resource endpoint, and select the model by deployment name.
- **Deployment name ≠ model name.** They are often the same, but not always.
- **Keep secrets out of code.** Use User Secrets locally and environment variables or Key Vault on servers.
- **Read the HTTP status code first.** 400 means a bad request or endpoint, 401 means authentication failed, 404 means the deployment wasn't found, and 429 means a quota limit.
- **The Kernel is the center of everything.** Every later step adds something to it: plugins, filters, vector stores and agents.

## 12. Glossary

| Term | Definition |
|---|---|
| **Azure OpenAI** | OpenAI models hosted in Azure, with enterprise security and quotas |
| **Microsoft Foundry** | Microsoft's portal and platform for building AI apps (formerly Azure AI Studio / Azure AI Foundry) |
| **Deployment** | One instance of a model inside your resource, with its own name and quota |
| **Global Standard** | A deployment type that routes requests to Azure data centers worldwide; pay per token |
| **Connector** | The SK component that talks to a specific AI provider |
| **KernelFunction** | Any callable unit in SK: a prompt or a C# method |
| **FunctionResult** | The object returned by a KernelFunction call |
| **User Secrets** | .NET's tool for storing development secrets outside the project |
